# Preset Sorter（预设排序器）

> 为 **TauriTavern**（SillyTavern 1.18 前端 + Tauri/Rust 后端，实机验证版本 2.3.0）编写的第三方前端扩展：
> 按 **导入时间** / **使用次数** / **最近使用** 对预设下拉框排序，并可把同一系列的多个版本折叠成一组：
> v1.3.0 起默认使用 **自定义分组下拉**（系列标题可点击折叠/展开，默认展开；原生 `<select>` 仍是唯一数据源），也可切回原生 `<optgroup>`。
> 排序依据与 **正序/倒序** 是两个独立控件；兼容原版 SillyTavern 与多平台（Windows/macOS/Linux/Android/iOS），无需任何存储权限。

- 版本：1.3.0
- 依赖：无（纯前端 ES Module，零构建、零第三方运行库）
- 隐私：不联网、不上传、不改动预设文件；只在 SillyTavern 的 `extension_settings` 中保存扩展设置与统计

---

## 1. 功能

- 在预设下拉框所在行增加一个紧凑的 **排序控件组**（例如「AI Response Configuration」中的 Chat Completion Presets 下拉框右侧）：
  排序图标 + **排序依据** 下拉框 + 独立的 **「倒序」复选框**（勾选=倒序，取消=正序）。
- 排序依据与方向（两个独立控件）：

  | 排序依据 | 正序（倒序未勾选） | 倒序（勾选） |
  | --- | --- | --- |
  | 默认排序 | 保持 SillyTavern 原始顺序（方向复选框禁用，不重排） | 同左（不重排） |
  | 导入时间 | 早 → 晚（最早导入在前） | 晚 → 早（最新导入在前） |
  | 使用次数 | 少 → 多（用得最少在前） | 多 → 少（用得最多在前） |
  | 最近使用 | 远 → 近（最久未用在前） | 近 → 远（最近用过在前） |

  选择「导入时间」时，读取不到文件时间的预设始终排在最后（正序/倒序都一样），其余预设按原顺序稳定排列。
- 排序只改变 `<option>` 的显示顺序，**不修改** 预设名称、内容、绑定关系与当前选中项；不触发 `change` 事件，不改变 SillyTavern 内存数据。
- 鼠标悬停预设项可查看「导入时间（来源） / 使用次数 / 最近使用」原生提示（始终开启，不影响选择）。
- 设置与统计持久化在 `settings.json` 的 `extension_settings["preset-sorter"]`；TauriTavern 与原版 SillyTavern 共用同一数据目录时统计可延续。
- 扩展设置面板（Extensions 设置区）：启用开关、默认排序依据、独立的「倒序」复选框、是否应用到全部预设管理器、刷新导入时间、重置使用统计、诊断信息。
- 从 1.0.x 升级时设置会 **静默迁移**（原来的「导入时间：早→晚」等模式自动转换为「排序依据+方向」，例如 `import-asc` → 导入时间 + 正序），不会丢失当前选择。
- **预设分组（v1.2.0 起）**：按「系列名」把同系列的多个版本归入一个系列分组（例如 `Virgo_Preset_1.55` 与 `Virgo_Preset_1.6` 归入 `Virgo_Preset` 组）。支持自动识别（智能/严格模式）与手动分组管理器；只改变下拉框展示，不合并/删除任何预设，关闭开关立即恢复平铺列表。
- **可折叠分组下拉（v1.3.0）**：默认的「折叠式自定义下拉」把当前预设显示为一个按钮，点击展开分组面板；系列标题默认展开、点击标题即可折叠/展开（折叠状态在页面打开期间保留），点击版本项直接选中。原生 `<select>` 仍保留在页面中作为唯一数据源（排序、工具栏、其他扩展、自动绑定全部照常工作）。可在设置中切回「原生分组下拉」（原生 `<optgroup>` 标题无法折叠）；自定义下拉异常时自动回退到原生分组视图。
- 支持全部 8 个预设管理器：OpenAI（对话补全）、TextGen、KoboldAI、NovelAI、上下文模板、指令模板、系统提示词、推理模板。分组对全部管理器生效。

| 环境 | 排序 | 导入时间来源 | 使用统计 |
| --- | --- | --- | --- |
| TauriTavern 桌面（Windows / macOS / Linux） | ✅ | 文件 `birthtime`（不可用时 `mtime`） | ✅ |

默认排序依据为「默认排序」，因此安装后不会立刻改变任何下拉框的顺序；在任意一个预设下拉框旁选择排序依据或勾选「倒序」后立即生效。

排序依据与方向相互独立：先选依据，再决定是否勾选「倒序」；选择「默认排序」时方向复选框自动禁用并变灰。
预设分组默认开启（智能模式）：自动识别只是建议，可在「分组管理器」中逐项调整或选择「不分组」；关闭分组开关会立即恢复平铺列表，所有预设与选中项保持不变。

### 2.1 移动端说明（Android / iOS）

- 排序控件组与设置面板均使用响应式布局：窄屏（≤480px）自动换行，不设固定宽度，不会把所在行撑出屏幕；
  若预设行空间不足导致行内控件组换行/被隐藏，仍可从「扩展设置 → Preset Sorter」面板使用同样的「排序依据 + 倒序」控件。
- 触控目标：排序依据下拉框与「倒序」复选框在移动端至少有约 32px 的可点击高度；复选框加大到 18px。
- 数据目录（`data_root`）：
  - Android：通常为 `/storage/emulated/0/Android/data/com.tauritavern.client/data`（外部应用私有目录；若不可用则使用内部应用目录）；
  - iOS：应用沙盒内 `Library/Application Support/com.tauritavern.client/data`。
- **无需任何存储权限/运行时授权**：扩展只读取应用自身数据目录下的预设 JSON 元数据；TauriTavern 在启动时已把 `data_root` 加入宿主 fs 授权范围。
- 路径解析优先使用 `get_user_directory`（全平台可用）；`get_runtime_paths` 仅桌面端存在，移动端会自动跳过，不影响导入时间排序。
- 导入时间来源：优先文件创建时间（`birthtime`）；Android 部分内核/FUSE 可能不提供创建时间，此时自动回退修改时间（`mtime`），仍不可用时回退首次发现时间，排序不会报错或崩溃。
- 移动端第三方扩展在 `APP_READY` 之后加载，扩展会等待宿主与下拉框就绪后再注入控件，因此首屏可能出现短暂延迟，属正常现象。

## 3. 安装

### 3.1 从 GitHub 安装（TauriTavern，推荐）

插件发布在 GitHub 仓库的独立分支上（仓库 `main` 分支是原项目，互不影响）：

1. 打开 TauriTavern →「扩展」/ Extensions →「Install extension」。
2. Git URL 填写：`https://github.com/sdfggggg/ST-PresetAutoSaveRealTime`
3. **Branch or tag name (optional)** 填写：`preset-sorter`（跟随最新版）或固定版本标签 `preset-sorter-v1.2.0`。
4. 选择「Install just for me」（当前用户）或「Install for all users」（全局），确认第三方扩展警告。
5. 安装完成后重启 TauriTavern（扩展在启动时加载；若显示禁用，勾选启用后重启）。

> TauriTavern 的安装对话框支持可选分支/标签名；原版 SillyTavern 的扩展安装不支持分支参数，请使用下方本地安装方式。

### 3.2 本地文件夹安装（离线/原版 SillyTavern 通用）

1. 找到数据目录（`data_root`）：
   - **Windows**：`%APPDATA%\com.tauritavern.client\data`
   - **macOS**：`~/Library/Application Support/com.tauritavern.client/data`
   - **Linux**：`~/.config/com.tauritavern.client/data`（或 `$XDG_CONFIG_HOME` 下）
   - **Android**：应用数据目录下的 `data/`（以应用内「设置 → 数据目录」显示为准）

2. 将本扩展整个 `preset-sorter/` 文件夹复制到：

## 4. 使用

1. 打开任意包含预设下拉框的面板（如「AI Response Configuration」）。
2. 在下拉框右侧找到新增的 **排序控件组**：
   - **排序依据** 下拉框：默认排序 / 导入时间 / 使用次数 / 最近使用；
   - **倒序** 复选框：勾选为倒序，取消为正序；选择「默认排序」时该复选框禁用（方向无意义）。
   两项选择会立即生效并持久化。
3. 需要更细的控制时，到「扩展设置 → Preset Sorter」：
   - **启用预设排序**：总开关，关闭后恢复 SillyTavern 原始顺序；
   - **默认排序依据** + **倒序** 复选框：全局默认设置（「应用到所有预设管理器」开启时即所有管理器使用该设置）；
   - **应用到所有预设管理器**：默认开启；关闭后可分别设置各预设管理器的排序依据与方向；
   - **刷新导入时间**：清除缓存并重新从 Tauri 宿主读取文件时间（批量复制预设后使用）；
   - **重置使用统计**：二次确认后清零使用次数与最近使用时间，保留导入时间。
4. 诊断信息会显示文件系统时间是否可用、数据目录/用户、已跟踪预设数、已解析导入时间数；面板会显示当前「排序依据 · 方向」提示。

### 4.1 方向（正序 / 倒序）语义

- **导入时间**：正序 = 早→晚（老预设在前）；倒序 = 晚→早（新预设在前）。读取不到时间的预设始终排最后。
- **使用次数**：正序 = 少→多（用得最少的在前）；倒序 = 多→少（用得最多的在前）。
- **最近使用**：正序 = 远→近（最久没用的在前）；倒序 = 近→远（最近用过的在前）。
- **默认排序**：方向不参与排序，始终恢复 SillyTavern 原始顺序。
- 主排序值相同时依次比较次排序值（使用次数：次数 → 最近使用；最近使用：最近使用 → 次数），仍相同则保持原顺序，结果稳定可复现。

### 4.2 从 1.0.x 升级（静默迁移）

- 旧版本保存的是组合模式字符串（如 `import-asc`、`usage-desc`）。1.1.0 首次加载时会自动转换为「排序依据 + 方向」：
  `default`→默认排序、`import-asc`→导入时间+正序、`import-desc`→导入时间+倒序、`usage-asc`/`usage-desc`→使用次数+方向、`recent-asc`/`recent-desc`→最近使用+方向。
- 迁移是 **无损且幂等** 的：不会丢失当前选择（例如你原来用的是 `import-asc`，升级后仍是「导入时间 + 正序」）；重复加载不会改变结果，设置会在下一次保存时写回新格式。
- 使用统计（`stats`）结构不变，升级后继续累积。

### 4.3 预设分组（原生 `<optgroup>`，v1.2.0）

- **原理**：只把预设 `<option>` 节点移动到浏览器原生的 `<optgroup label="系列 (N)">` 里；不改名称、不改 value、不删除任何预设、不触发 `change` 事件，SillyTavern 的切换/改名/删除/导入逻辑完全不受影响。桌面与手机的系统原生下拉选择器都会显示分组标题。
- **自动识别**（设置中的「自动识别模式」）：
  - **智能**（默认）：先按版本后缀解析系列名（`v1.2`、`1.71v-T`、`Beta`、`2026-05-01`、`第二版`、`III` 等），识别不到时再用保守的「第一个数字前的名称前缀」启发式（前缀至少 2 个字符、排除 generic 名称、且同前缀至少 2 个成员才成组）。适合国内常见命名（`【春茶】1.71v-T`、`ny预设3.2`、`kemini…`）。
  - **严格**：只用版本后缀解析成组，最保守，几乎不会误分组。
  - 自动分组 **至少需要 2 个成员**；只有一个版本或无法识别的预设保持独立选项。
- **排序整合**：分组与独立预设一起用当前「排序依据 + 方向」排序——组使用成员聚合值（导入时间取组内最早/最新、使用次数取组内最多/最少等）；组内版本按自然版本号升序排列（`1.2 < 1.10`，无法解析版本的排最后）。
- **分组管理器**（设置面板 →「管理分组…」）：可搜索预设，为每个预设输入分组名（相同名称归组）、查看自动识别建议、勾选「不分组」保持独立；「保存分组」写入覆盖表，「恢复自动分组」清空所有手动设置。手动覆盖始终优先于自动识别。
- **限制 / 已知情况**：自动识别只是**建议**，不保证符合每个人的命名习惯；名称完全无规律时不会成组，请用分组管理器手动整理或切换「严格」模式。真实数据审计（本机 72 个 OpenAI 预设，命名差异极大）：
  - **严格模式**：9 个多版本分组 / 24 个预设（`V0` 5、`Virgo_Preset` 3、`ny预设` 3、`gal_adaption_of_tera` 3、`Genesis_Presets` 2、`Lyean` 2、`【春茶】` 2、`斯拉预设` 2、`XHM` 2），其余 48 个保持独立。
  - **智能模式（默认）**：10 个分组 / 27 个预设，即上述分组再加上 `【kemini】` 2 个、`XHM` 扩为 3 个（`XHM3_v0.2b…` 也归入 `XHM`），其余 45 个保持独立。`V3.0.0_*`、`44beta*`、`V0.a11` 等相近前缀名称不会被误分组。
  - 自动识别只是建议，可用「不分组/手动分组」纠正；`XHM-Claude3.0` 等同名前缀但结构不同的预设保持独立。
- **关闭分组**：设置面板的「启用预设分组」关闭后立即恢复平铺列表，手动分组设置会保留，重新开启即恢复。

### 4.4 下拉展示方式（v1.3.0：自定义折叠下拉 / 原生分组）

设置面板的分组区域新增「下拉展示方式」：

- **折叠式自定义下拉（默认）**：预设行显示一个按钮（当前预设名 + 下拉箭头）。点击展开固定定位面板；系列标题带箭头与成员数（如 `Virgo_Preset (3)`），**默认展开**，点击标题只折叠/展开该系列（不影响当前选中预设），折叠状态保存在扩展内存中、页面重开恢复默认展开；点击版本项会写入原生 `<select>` 的 value 并派发 **原生 `change` 事件**，SillyTavern 工具栏/其他扩展/自动绑定无需任何适配。面板支持键盘（Enter/Space/↓ 打开、↑/↓ 移动、Home/End、Enter/Space 选中、Esc 关闭、Tab 关闭）、点击面板外关闭、窗口滚动/缩放重新定位；移动端面板最高约 60vh 并保留安全区边距，触控行高 ≥32px。自定义视图激活时，隐藏的原生 `<select>` 保持**平铺且按当前排序**的选项列表，供 ST 与其他扩展读取。
- **原生分组下拉**：沿用 v1.2.0 的浏览器原生 `<optgroup>` 分组（桌面/手机系统原生选择器），标题不可折叠。
- **安全兜底**：自定义下拉初始化或同步失败时，该预设管理器自动回退到原生分组视图（不会让下拉框不可用）；关闭「启用预设分组」或切回原生视图会销毁自定义控件并恢复普通原生 `<select>`。

## 5. 导入时间：来源与限制（请阅读）

扩展按以下优先级确定一个预设的「导入时间」：

1. 预设 JSON 文件的 **创建时间**（`birthtime`，经 Tauri 宿主 `plugin:fs` 读取）；
2. 若创建时间不可用，使用 **修改时间**（`mtime`）；
3. 若无法访问文件系统（原版 SillyTavern、权限受限、自定义目录不可读等），使用 **首次发现时间**（扩展第一次看到该预设的时间）。

限制：

- **批量复制/迁移数据的存量预设**：文件创建时间会变成复制时间（同一毫秒级窗口）。此时排序是确定且稳定的，但反映的是复制顺序，而不是你当初逐个导入的时间；扩展无法恢复已被复制的历史顺序。安装后可点击「刷新导入时间」重新读取，但对存量数据结果相同。
- **更新预设**：在提供 `birthtime` 的平台不会改变导入时间；仅提供 `mtime` 的平台会把更新视为更近的时间。
- **首次发现时间**：从扩展第一次运行开始记录；对安装前就存在的预设无法凭空得到真实导入时间。

> 本机实测（72 个真实预设）：文件创建时间跨度约 83ms、66 个不同毫秒值，属于典型的批量迁移数据。排序仍然确定、可复现；新导入的预设会获得真实的创建时间并被正确排序。

## 6. 使用统计语义

- 「使用次数 / 最近使用」统计的是 **当前 API 的预设实际用于生成对话** 的次数与时间：监听 SillyTavern 的 `GENERATION_AFTER_COMMANDS` 事件，在非 dry-run、非 `quiet` 生成时记录当前预设管理器所选中的预设。
- 只统计当前激活 API 的预设（例如使用 OpenAI 对话补全时统计 Chat Completion Preset；切换到 TextGen/Kobold/Novel 时统计对应预设，高级格式化的模板同理由各自管理器在激活时统计）。
- 统计从扩展安装后开始累积，不包含历史数据（SillyTavern 不保存预设历史使用记录）。
- 数据保存在 `extension_settings["preset-sorter"]`；换用同一数据目录的 TauriTavern/SillyTavern 时继续累积。
- 重命名预设会迁移其统计；删除预设会移除对应统计。
- 关闭「启用预设排序」时不会记录新的使用统计；如需长期统计请保持开启（排序依据仍可选择「默认排序」，不影响顺序）。

## 7. 性能

- 启动时优先用内存/持久化缓存立即排序，不阻塞页面；文件时间读取在浏览器空闲时批量异步执行（并发 4、单次超时 4s），缓存命中后不再访问磁盘。
- 重排使用一次 `DocumentFragment` 批量提交，避免逐项触发布局；重复排序会先比较顺序，一致时零 DOM 操作。
- 仅监听受支持的预设下拉框（`childList`），回调批量合并，忽略自身重排产生的变更；tooltip 仅在内容变化时写入。
- 实测（Node 基准，`tests/perf/bench.mjs`）：5000 个预设排序约 0.4–2.3ms（使用次数/最近使用方向略高）；1500 项 DOM 重排约 3.8ms；重复应用零变更。

## 8. 故障排查

- **看不到排序控件**：确认扩展已启用并重启；确认当前面板的预设下拉框带 `data-preset-manager-for` 属性（SillyTavern 1.18+ / TauriTavern）。
- **导入时间显示「首次出现」**：宿主文件时间读取不可用。打开扩展设置面板的「诊断信息」查看原因；原版 SillyTavern 浏览器环境属预期降级。
- **排序后当前选中预设变了**：不应发生（扩展会保持选中值）。如遇到请附带浏览器控制台日志反馈。
- **设置文件过大**：统计按每个预设管理器最多 600 条自动裁剪，不会无限增长。
- **调试**：浏览器控制台可读取只读诊断对象 `window.__PRESET_SORTER__.getStatus()`。

## 9. 卸载

- 在「扩展」面板禁用，或删除扩展目录；
- 可选：清除 `settings.json` → `extension_settings["preset-sorter"]` 键，移除本扩展的设置与统计（不影响任何预设文件）。
